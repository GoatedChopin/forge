# Environment Variables

FORGE provides typesafe environment variable access through the `EnvAccess` trait. Instead of scattering `std::env::var()` calls throughout your code, use context methods that provide better error messages and are easily testable.

## Why Use EnvAccess?

Direct `std::env::var()` calls have several problems:

- **No type safety**: Returns `Result<String, VarError>`, requiring manual parsing
- **Typos compile**: `STRIPE_KEY` vs `STRIPE_API_KEY` won't be caught until runtime
- **Hard to test**: No clean way to mock environment in tests
- **Scattered access**: No central view of what env vars your app needs

The `EnvAccess` trait solves these:

```rust
// Before: scattered, untyped, hard to test
let key = std::env::var("STRIPE_API_KEY").expect("missing key");
let timeout: u32 = std::env::var("TIMEOUT").unwrap().parse().unwrap();

// After: centralized, typed, testable
let key = ctx.env_require("STRIPE_API_KEY")?;
let timeout: u32 = ctx.env_parse("TIMEOUT")?;
```

## Available Methods

All context types (`QueryContext`, `MutationContext`, `JobContext`, `CronContext`, `WorkflowContext`) implement `EnvAccess`:

| Method | Returns | Description |
|--------|---------|-------------|
| `env(key)` | `Option<String>` | Get optional variable |
| `env_or(key, default)` | `String` | Get with fallback |
| `env_require(key)` | `Result<String>` | Get required variable |
| `env_parse<T>(key)` | `Result<T>` | Parse required variable |
| `env_parse_or<T>(key, default)` | `Result<T>` | Parse with fallback |
| `env_contains(key)` | `bool` | Check if set |

## Usage

### Import the Trait

The `EnvAccess` trait is included in the prelude:

```rust
use forge::prelude::*;  // EnvAccess is included
```

### Optional Variables

```rust
#[forge::query]
async fn get_settings(ctx: &QueryContext) -> Result<Settings> {
    // Returns None if not set
    let theme = ctx.env("DEFAULT_THEME");

    // Returns default if not set
    let page_size = ctx.env_or("PAGE_SIZE", "20");

    // Check if set without reading
    let debug_enabled = ctx.env_contains("DEBUG");

    // ...
}
```

### Required Variables

```rust
#[forge::mutation]
async fn charge_card(ctx: &MutationContext, input: ChargeInput) -> Result<Charge> {
    // Returns error if not set: "Required environment variable 'STRIPE_API_KEY' not set"
    let api_key = ctx.env_require("STRIPE_API_KEY")?;

    let response = ctx.http()
        .post("https://api.stripe.com/v1/charges")
        .bearer_auth(&api_key)
        .json(&input)
        .send()
        .await?;

    // ...
}
```

### Typed Variables

```rust
#[forge::job]
async fn process_batch(ctx: &JobContext, input: BatchInput) -> Result<()> {
    // Parse as u32, error if missing or invalid
    let batch_size: u32 = ctx.env_parse("BATCH_SIZE")?;

    // Parse with default (only errors if set but unparseable)
    let max_retries: u32 = ctx.env_parse_or("MAX_RETRIES", 3)?;

    // Parse boolean
    let dry_run: bool = ctx.env_parse_or("DRY_RUN", false)?;

    // Parse duration in seconds
    let timeout_secs: u64 = ctx.env_parse_or("TIMEOUT_SECS", 30)?;

    // ...
}
```

### Error Messages

The methods provide clear error messages:

```rust
// Missing required variable
ctx.env_require("API_KEY")
// Error: "Required environment variable 'API_KEY' not set"

// Parse error
ctx.env_parse::<u32>("PORT")  // when PORT="abc"
// Error: "Failed to parse env var 'PORT' value 'abc': invalid digit found in string"
```

## Testing

Test contexts use `MockEnvProvider` which records accessed keys for verification.

### Setting Mock Values

```rust
use forge::prelude::*;

#[tokio::test]
async fn test_with_env_vars() {
    let ctx = TestMutationContext::builder()
        .with_env("STRIPE_API_KEY", "sk_test_xxx")
        .with_env("TIMEOUT", "60")
        .build();

    // Your function will use the mocked values
    assert_eq!(ctx.env("STRIPE_API_KEY"), Some("sk_test_xxx".to_string()));
    assert_eq!(ctx.env_parse::<u32>("TIMEOUT").unwrap(), 60);
}
```

### Setting Multiple Variables

```rust
use std::collections::HashMap;

#[tokio::test]
async fn test_with_multiple_vars() {
    let mut env_vars = HashMap::new();
    env_vars.insert("API_KEY".to_string(), "secret".to_string());
    env_vars.insert("API_URL".to_string(), "https://api.example.com".to_string());
    env_vars.insert("TIMEOUT".to_string(), "30".to_string());

    let ctx = TestQueryContext::builder()
        .with_envs(env_vars)
        .build();

    // ...
}
```

### Verifying Access

You can verify which environment variables were accessed:

```rust
#[tokio::test]
async fn test_env_access_verification() {
    let ctx = TestMutationContext::builder()
        .with_env("REQUIRED_KEY", "value")
        .with_env("OPTIONAL_KEY", "other")
        .build();

    // Call your function
    let _ = ctx.env_require("REQUIRED_KEY");

    // Verify which keys were accessed
    ctx.env_mock().assert_accessed("REQUIRED_KEY");
    ctx.env_mock().assert_not_accessed("OPTIONAL_KEY");

    // Get all accessed keys
    let accessed = ctx.env_mock().accessed_keys();
    assert!(accessed.contains(&"REQUIRED_KEY".to_string()));
}
```

### Testing Missing Variables

```rust
#[tokio::test]
async fn test_missing_env_var() {
    let ctx = TestMutationContext::builder().build();  // No env vars set

    let result = ctx.env_require("MISSING_KEY");
    assert!(result.is_err());

    // Check error message
    let err = result.unwrap_err();
    assert!(err.to_string().contains("MISSING_KEY"));
}
```

### Testing Parse Errors

```rust
#[tokio::test]
async fn test_invalid_env_var() {
    let ctx = TestQueryContext::builder()
        .with_env("PORT", "not_a_number")
        .build();

    let result: Result<u32> = ctx.env_parse("PORT");
    assert!(result.is_err());

    let err = result.unwrap_err();
    assert!(err.to_string().contains("not_a_number"));
}
```

## Real-World Examples

### API Integration

```rust
#[forge::mutation]
async fn send_email(ctx: &MutationContext, input: EmailInput) -> Result<EmailResult> {
    let api_key = ctx.env_require("SENDGRID_API_KEY")?;
    let from_email = ctx.env_or("FROM_EMAIL", "noreply@example.com");
    let sandbox: bool = ctx.env_parse_or("SENDGRID_SANDBOX", false)?;

    let mut request = ctx.http()
        .post("https://api.sendgrid.com/v3/mail/send")
        .bearer_auth(&api_key)
        .json(&build_email(&input, &from_email));

    if sandbox {
        request = request.header("X-Sandbox-Mode", "true");
    }

    // ...
}

#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn test_send_email() {
        let ctx = TestMutationContext::builder()
            .with_env("SENDGRID_API_KEY", "SG.test_key")
            .with_env("SENDGRID_SANDBOX", "true")
            .mock_http_json("https://api.sendgrid.com/*", serde_json::json!({
                "message": "success"
            }))
            .build();

        // Test your function...
        ctx.env_mock().assert_accessed("SENDGRID_API_KEY");
    }
}
```

### Feature Flags

```rust
#[forge::query]
async fn list_features(ctx: &QueryContext) -> Result<Vec<Feature>> {
    let mut features = vec![];

    if ctx.env_contains("FEATURE_DARK_MODE") {
        features.push(Feature::DarkMode);
    }

    if ctx.env_parse_or("FEATURE_BETA_UI", false)? {
        features.push(Feature::BetaUi);
    }

    let max_items: usize = ctx.env_parse_or("MAX_FEATURE_ITEMS", 100)?;

    Ok(features.into_iter().take(max_items).collect())
}
```
