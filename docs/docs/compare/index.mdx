# FORGE vs. Alternatives

FORGE takes a different approach from most backend solutions. Here's how it compares.

## Quick Comparison

| Feature | FORGE | Supabase | Firebase | PocketBase |
|---------|-------|----------|----------|------------|
| **Deployment** | Single binary | Hosted + Self-host | Hosted only | Single binary |
| **Database** | PostgreSQL | PostgreSQL | Firestore/RTDB | SQLite |
| **Language** | Rust | Any (via REST) | Any (via SDK) | Go + JS |
| **Type Safety** | Full (Rust types) | Partial (generated) | Partial (rules) | Partial |
| **Background Jobs** | Built-in | Edge Functions | Cloud Functions | None |
| **Workflows** | Built-in | None | None | None |
| **Cron Jobs** | Built-in | pg_cron extension | Cloud Scheduler | None |
| **Real-time** | PostgreSQL NOTIFY | PostgreSQL replication | Native | SSE |
| **Auth** | Built-in JWT | Built-in | Built-in | Built-in |
| **Self-hosting** | Native | Complex | No | Native |
| **Vendor lock-in** | None | Low | High | None |
| **Cost at scale** | $$ | $$$ | $$$$ | $ |

## Choose FORGE if you want:

- **Single binary simplicity** - No Redis, Kafka, or message queues
- **Type-safe Rust backend** - Catch errors at compile time
- **Built-in background processing** - Jobs, crons, and workflows without extra services
- **PostgreSQL only** - Leverage 30+ years of database reliability
- **Zero vendor lock-in** - Run anywhere, migrate anytime
- **Predictable costs** - No per-request pricing surprises

## When to NOT use FORGE

Be honest with yourself - FORGE isn't for everyone:

- **You need NoSQL** - FORGE is PostgreSQL-only
- **You want managed hosting** - FORGE is self-hosted (though Railway/Render deploy in 1 click)
- **You prefer JavaScript/Python** - FORGE backend is Rust-only
- **You need GraphQL** - FORGE uses REST/gRPC
- **You have an existing backend** - FORGE is a full framework, not a library
