# FORGE vs. PocketBase

Both FORGE and PocketBase are single-binary backends designed for simplicity. Here's how they differ.

## Architecture Comparison

| Aspect | FORGE | PocketBase |
|--------|-------|------------|
| **Language** | Rust | Go |
| **Database** | PostgreSQL | SQLite (embedded) |
| **Extensibility** | Rust code | Go hooks + JS |
| **Type Safety** | Full Rust types | JavaScript (loose) |
| **Target Scale** | Small → Large | Small → Medium |
| **Background Jobs** | Built-in | None |

## Philosophy

### FORGE: Full Framework

FORGE is a **complete application framework** - you write your business logic in Rust with full type safety, compile-time checks, and integrated background processing.

```rust
#[forge::mutation]
pub async fn create_order(ctx: &MutationContext, input: OrderInput) -> Result<Order> {
    let user_id = ctx.require_user_id()?;

    // Type-safe database query
    let order = sqlx::query_as!(Order, r#"
        INSERT INTO orders (user_id, items, total)
        VALUES ($1, $2, $3)
        RETURNING *
    "#, user_id, &input.items, input.total)
    .fetch_one(ctx.db())
    .await?;

    // Dispatch background job
    ctx.dispatch_job("process_order", serde_json::json!({
        "order_id": order.id
    })).await?;

    Ok(order)
}
```

### PocketBase: Instant Backend

PocketBase is an **instant backend** - create collections in the admin UI, get REST APIs automatically. Extend with JavaScript hooks when needed.

```javascript
// PocketBase JS hook
routerAdd("POST", "/api/custom", (c) => {
    const data = $apis.requestInfo(c).data;
    // Process data
    return c.json(200, { success: true });
});
```

## Feature Comparison

### Database

| Feature | FORGE | PocketBase |
|---------|-------|------------|
| Engine | PostgreSQL | SQLite |
| Concurrent writes | Excellent | Limited (single-writer) |
| Transactions | Full ACID | WAL mode |
| Scale ceiling | Very high | ~100K users |
| Horizontal scaling | Yes (read replicas) | No |
| Data modeling | SQL schema | Collection UI |

**FORGE advantage:** PostgreSQL handles concurrent writes, complex queries, and scales to millions of users.

**PocketBase advantage:** Zero database setup, embedded SQLite, perfect for prototypes and small apps.

### Background Processing

| Feature | FORGE | PocketBase |
|---------|-------|------------|
| Background Jobs | Built-in | None |
| Cron Jobs | Built-in | None |
| Workflows | Built-in | None |
| Progress Tracking | Built-in | N/A |
| Retries | Automatic | N/A |

**FORGE:**
```rust
#[forge::job]
#[retry(max_attempts = 3)]
pub async fn send_email(ctx: &JobContext, input: EmailInput) -> Result<()> {
    ctx.progress(50, "Sending...")?;
    send_via_smtp(&input).await?;
    ctx.progress(100, "Sent!")?;
    Ok(())
}

#[forge::cron("0 9 * * *")]  // 9 AM daily
pub async fn daily_report(ctx: &CronContext) -> Result<()> {
    generate_and_send_report(ctx.db()).await
}
```

**PocketBase:** No built-in background processing. You need external tools (cron, task queues) or trigger via webhooks.

### Real-time

| Feature | FORGE | PocketBase |
|---------|-------|------------|
| Mechanism | PostgreSQL NOTIFY | SSE (Server-Sent Events) |
| Bidirectional | WebSocket | No (SSE is one-way) |
| Custom events | Yes | No (collection changes only) |
| Filtering | Server logic | Collection + record rules |

**FORGE:**
```rust
// Broadcast custom event
ctx.broadcast("game:player_moved", &MoveEvent { player, x, y }).await?;
```

**PocketBase:**
```javascript
// Subscribe to collection changes only
pb.collection('posts').subscribe('*', function (e) {
    console.log(e.action, e.record);
});
```

### Extensibility

| Approach | FORGE | PocketBase |
|----------|-------|------------|
| Primary | Rust code | Admin UI |
| Custom Logic | Rust functions | Go/JS hooks |
| Type Safety | Full | Partial |
| IDE Support | Excellent | Limited |
| Hot Reload | Cargo watch | Built-in |

**FORGE:** Your entire backend is code. Full IDE support, refactoring, type checking.

**PocketBase:** Define schema in UI, add hooks when needed. Faster to start, less control.

### Deployment

| Aspect | FORGE | PocketBase |
|--------|-------|------------|
| Binary Size | ~15-30MB | ~30-40MB |
| Memory Usage | ~50-100MB | ~30-50MB |
| Dependencies | PostgreSQL | None (SQLite embedded) |
| Docker | Yes | Yes |
| 1-click Deploy | Railway, Render, Fly | PocketHost, Railway, Fly |

**FORGE:**
```bash
# Requires PostgreSQL
docker run -d postgres:16-alpine
./my-forge-app
```

**PocketBase:**
```bash
# Truly single binary - no external database
./pocketbase serve
```

## When to Choose FORGE

Choose FORGE when:

1. **You need real background processing** - Jobs, crons, workflows with compensation
2. **You expect to scale** - PostgreSQL handles millions of users
3. **You want full type safety** - Rust catches errors at compile time
4. **You have complex business logic** - Full programming language, not hooks
5. **You need concurrent writes** - PostgreSQL >> SQLite for write-heavy apps
6. **You want durable workflows** - Multi-step processes with automatic rollback

## When to Choose PocketBase

Choose PocketBase when:

1. **You're building a prototype** - Fastest path to working backend
2. **You want zero dependencies** - No database to set up
3. **You prefer visual schema design** - Admin UI is excellent
4. **Your app is read-heavy** - SQLite reads are very fast
5. **You need admin panel included** - PocketBase's admin UI is built-in
6. **You're building a small-medium app** - Perfect for &lt;100K users

## Performance Comparison

### Read Performance (ops/sec)

| Operation | FORGE (PostgreSQL) | PocketBase (SQLite) |
|-----------|-------------------|---------------------|
| Simple read | ~50,000 | ~100,000 |
| With JOIN | ~30,000 | ~20,000 |
| Concurrent reads | Scales | Scales |

### Write Performance (ops/sec)

| Operation | FORGE (PostgreSQL) | PocketBase (SQLite) |
|-----------|-------------------|---------------------|
| Simple insert | ~20,000 | ~5,000 |
| Concurrent inserts | ~15,000 | ~1,000 (single-writer) |
| Transactions | Parallel | Sequential |

**Key insight:** PocketBase is faster for reads on small datasets. FORGE (PostgreSQL) is dramatically better for concurrent writes and complex queries.

## The Migration Question

**PocketBase → FORGE:**
- Export SQLite data
- Design PostgreSQL schema
- Rewrite hooks as Rust functions
- Add background jobs you couldn't have before

**FORGE → PocketBase:**
- Rare (usually for simplification)
- Export PostgreSQL data
- Create collections
- Rewrite jobs as webhooks/cron scripts

## Summary

| You should use... | If you value... |
|-------------------|-----------------|
| **FORGE** | Type safety, background processing, PostgreSQL scale, workflows |
| **PocketBase** | Simplicity, zero deps, admin UI, fast prototyping |

**TL;DR:** PocketBase is a fantastic tool for rapid development and small apps. FORGE is for production apps that need background processing, workflows, and PostgreSQL's power.

Use PocketBase to prototype, then evaluate FORGE when you need more power. Or start with FORGE if you know you'll need background jobs and complex workflows.
