# Quick Start

Let's build a working FORGE app in 5 minutes. By the end, you'll have a full-stack app with a database, API, and reactive frontend.

## Prerequisites

Before starting, make sure you have:

- **Docker** - [Install Docker](https://docs.docker.com/get-docker/)

That's it! Docker is the only prerequisite. All build tools (Rust, Bun) run inside containers.

```bash
# Check Docker is installed
docker --version
```

## Step 1: Install FORGE CLI

```bash
# Quick install (recommended)
curl -fsSL https://tryforge.dev/install.sh | sh

# Or with Cargo (if you have Rust installed)
cargo install forgex
```

Verify it works:

```bash
forge --version
```

## Step 2: Create Your Project

```bash
# Create a new FORGE project with demo examples
forge new my-app --demo
cd my-app
```

:::tip Starting from scratch?
Use `forge new my-app --minimal` for clean scaffolding without example code. This is useful when you're experienced with FORGE and want to build from scratch rather than modify the demo app.
:::

This creates a complete project structure:

```
my-app/
├── Cargo.toml           # Rust dependencies
├── forge.toml           # FORGE configuration
├── .env                 # Environment variables
├── Dockerfile           # Multi-stage Docker build
├── docker-compose.yml   # Development environment
├── migrations/          # SQL migrations
│   └── 0001_initial.sql
├── src/
│   ├── main.rs          # Entry point
│   ├── schema/          # Data models
│   └── functions/       # Your API functions
└── frontend/            # Svelte 5 app
    ├── package.json
    └── src/
```

## Step 3: Start Development

```bash
forge dev
```

That's it! This single command runs `docker compose up --build` which:

1. **Starts PostgreSQL** container with health checks
2. **Builds and runs your Rust backend** with hot reload (cargo-watch)
3. **Installs frontend dependencies** and starts the dev server
4. **Opens your browser** automatically

You should see:

```
🚀 Starting FORGE development environment...

  ✓ docker found

  → Running: docker compose up --build

[+] Building...
[+] Running 3/3
 ✔ Container my-app-db-1        Healthy
 ✔ Container my-app-backend-1   Started
 ✔ Container my-app-frontend-1  Started
```

### Development Commands

| Command | Description |
|---------|-------------|
| `forge dev` | Start all services (postgres + backend + frontend) |
| `forge dev down` | Stop all services |
| `forge dev down --clean` | Stop services and remove database volume |

## Step 4: Explore

- **App**: http://localhost:5173 - Your Svelte frontend
- **Dashboard**: http://localhost:8080/_dashboard - Admin panel
- **API**: http://localhost:8080/rpc - Backend endpoints

The dashboard shows:
- **Cluster health** - Node status
- **Jobs** - Background job queue
- **Logs** - Real-time logs
- **Metrics** - Request counts, latency

## What Just Happened?

You now have:

1. **A PostgreSQL database** running in Docker with your schema
2. **A Rust backend** with hot reload (cargo-watch) and auto-generated API endpoints
3. **A Svelte frontend** with reactive data fetching
4. **Real-time updates** via WebSocket
5. **An admin dashboard** for monitoring

All from two commands: `forge new --demo` and `forge dev`.

## Your First Change

Let's add a simple feature. Open `src/functions/users.rs`:

```rust
use forge::prelude::*;

#[derive(Debug, Serialize, Deserialize, sqlx::FromRow)]
pub struct User {
    pub id: Uuid,
    pub email: String,
    pub name: String,
    pub created_at: DateTime<Utc>,
}

#[forge::query]
pub async fn list_users(ctx: &QueryContext) -> Result<Vec<User>> {
    sqlx::query_as("SELECT * FROM users ORDER BY created_at DESC")
        .fetch_all(ctx.db())
        .await
        .map_err(Into::into)
}
```

The frontend can now use this query:

```svelte
<script>
  import { subscribe } from '$lib/forge';

  const users = subscribe('list_users', {});
</script>

{#if $users.loading}
  <p>Loading...</p>
{:else}
  {#each $users.data ?? [] as user}
    <p>{user.name} ({user.email})</p>
  {/each}
{/if}
```

**Changes sync automatically!** When you save a file, cargo-watch rebuilds the backend. When you add a user, the list updates in real-time.

## Production Build

The included Dockerfile is production-ready with a minimal Alpine image:

```bash
# Build production image (~50MB final image)
docker build -t my-app --target production .

# Run with external PostgreSQL
docker run -d \
  -e DATABASE_URL=postgres://user:pass@host/db \
  -p 8080:8080 \
  my-app
```

The multi-stage Dockerfile:
- **dev**: Hot reload with cargo-watch (for development)
- **frontend-builder**: Builds the Svelte frontend
- **builder**: Compiles the Rust binary with embedded frontend
- **production**: Minimal Alpine runtime (~50MB)

## Troubleshooting

### "docker: command not found"

Install Docker: https://docs.docker.com/get-docker/

### Port already in use

Change the ports in `docker-compose.yml`:
```yaml
services:
  backend:
    ports:
      - "8081:8080"  # Change 8080 to 8081
```

### Database connection issues

Reset the database:
```bash
forge dev down --clean
forge dev
```

### Build is slow

The first build downloads Rust dependencies and compiles them. Subsequent builds use Docker's cache and are much faster.

To speed up development:
- The Dockerfile caches dependencies in named volumes (`cargo_cache`, `target_cache`)
- Only changed files trigger rebuilds
- cargo-watch only watches relevant directories
