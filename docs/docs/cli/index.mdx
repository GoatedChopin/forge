# CLI Reference

The `forge` CLI tool helps you create, develop, and manage FORGE projects.

## Installation

```bash
# Quick install (recommended)
curl -fsSL https://tryforge.dev/install.sh | sh

# Or build from source
git clone https://github.com/isala404/forge
cd forge
cargo install --path crates/forge
```

## Commands Overview

| Command | Description |
|---------|-------------|
| `forge new` | Create a new project |
| `forge check` | Validate project setup |
| `forge dev` | Start development environment |
| `forge add` | Add a function |
| `forge generate` | Generate TypeScript types |
| `forge migrate` | Run database migrations |
| `forge run` | Start the server |

## forge new

Create a new FORGE project. You must choose a template mode.

```bash
forge new <project-name> --demo|--minimal [options]
```

**Arguments:**
- `<project-name>` - Name of the project (also used as directory name)

**Template Modes (required - choose one):**

| Option | Description |
|--------|-------------|
| `--demo` | Full demo project with working examples (User CRUD, jobs, workflows, cron tasks, external API actions, complete frontend UI) |
| `--minimal` | Clean project with just the structure (empty directories with commented examples, starter frontend) |

**Additional Options:**

| Option | Description |
|--------|-------------|
| `-o, --output` | Output directory (defaults to project name) |

**Examples:**

```bash
# Create a full demo project - learn FORGE with working examples
forge new my-app --demo

# Create a clean project - start fresh with just the scaffolding
forge new my-app --minimal
```

:::tip Choosing a template
- Use `--demo` if you're learning FORGE or want working examples to build from
- Use `--minimal` if you're experienced and want a clean slate
:::

**Demo project structure** (`--demo`):
```
my-app/
├── Cargo.toml
├── forge.toml           # FORGE configuration
├── .env                 # Environment variables
├── src/
│   ├── main.rs          # Entry point with registered functions
│   ├── schema/
│   │   ├── mod.rs
│   │   └── user.rs      # User model example
│   └── functions/
│       ├── mod.rs
│       ├── users.rs     # CRUD queries/mutations
│       ├── export_users_job.rs
│       ├── heartbeat_stats_cron.rs
│       ├── account_verification_workflow.rs
│       └── get_bitcoin_price_action.rs
├── migrations/
│   └── 0001_initial.sql # User tables migration
└── frontend/
    ├── package.json
    ├── src/
    │   ├── routes/+page.svelte  # Full demo UI
    │   └── lib/forge/           # Generated types & API
    └── ...
```

**Minimal project structure** (`--minimal`):
```
my-app/
├── Cargo.toml
├── forge.toml
├── .env
├── src/
│   ├── main.rs          # Entry point with commented examples
│   ├── schema/
│   │   └── mod.rs       # Empty, with usage comments
│   └── functions/
│       └── mod.rs       # Empty, with usage comments
├── migrations/
│   └── 0001_initial.sql # Empty migration template
└── frontend/
    ├── package.json
    ├── src/
    │   ├── routes/+page.svelte  # Starter page
    │   └── lib/forge/           # Minimal types
    └── ...
```

## forge check

Validate your project setup and dependencies.

```bash
forge check [options]
```

**Options:**

| Option | Default | Description |
|--------|---------|-------------|
| `-c, --config` | `forge.toml` | Path to configuration file |
| `--db` | `true` | Check database connectivity |

**What it checks:**

1. **Configuration** - `forge.toml` exists and is valid TOML
2. **Directory structure** - Required directories exist (`src/schema/`, `src/functions/`, `migrations/`)
3. **Environment** - `.env` file and `DATABASE_URL` variable
4. **Database** - PostgreSQL connection and version (optional)
5. **Frontend** - `package.json` and dependencies (if frontend exists)

**Example output:**

```

  ✓ forge.toml found
  ✓ forge.toml is valid TOML
  ✓ [project] section found
  ✓ [database] section found

  ✓ src/functions/ directory exists
  ✓ migrations/ directory exists
    → 3 migration file(s) found
  ✓ .env file found
  ✓ DATABASE_URL is set
    → postgres://user:****@localhost/myapp

  ⋯ Checking database connection...
  ✓ Database connection successful
    → PostgreSQL 16.1

✅ All checks passed! Ready to run.

  forge dev            Start development
```

## forge dev

Start the full development environment (backend + frontend) with hot reload.

```bash
forge dev [options]
```

**Options:**

| Option | Default | Description |
|--------|---------|-------------|
| `-p, --port` | `8080` | Backend HTTP port |
| `--backend-only` | `false` | Only start backend |
| `--frontend-only` | `false` | Only start frontend |
| `--no-open` | `false` | Don't open browser |

**Examples:**

```bash
# Start everything (backend + frontend + open browser)
forge dev

# Start only backend on port 3000
forge dev --backend-only --port 3000

# Start only frontend
forge dev --frontend-only

# Start without opening browser
forge dev --no-open
```

**Output:**

```
🔧 Starting FORGE development environment...

Backend starting on http://localhost:8080
Frontend starting on http://localhost:5173

📊 Dashboard: http://localhost:8080/_dashboard
🌐 App: http://localhost:5173

Press Ctrl+C to stop all services
```

## forge add

Add a new function to your project.

```bash
forge add <type> <name>
```

**Arguments:**
- `<type>` - Function type: `query`, `mutation`, `action`, `job`, `cron`, `workflow`
- `<name>` - Function name (snake_case)

**Examples:**

```bash
# Add a query
forge add query list_users

# Add a mutation
forge add mutation create_user

# Add a job
forge add job send_email

# Add a cron
forge add cron daily_cleanup

# Add a workflow
forge add workflow process_order
```

**Generated Files:**

Query:
```rust
// src/functions/queries/list_users.rs
use forge::prelude::*;

#[forge::query]
pub async fn list_users(ctx: &QueryContext) -> Result<Vec<User>> {
    todo!("Implement list_users")
}
```

Job:
```rust
// src/functions/jobs/send_email.rs
use forge::prelude::*;

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SendEmailInput {
    // Add input fields
}

#[forge::job]
pub async fn send_email(ctx: &JobContext, input: SendEmailInput) -> Result<()> {
    todo!("Implement send_email")
}
```

## forge generate

Generate TypeScript types from your Rust code.

```bash
forge generate
```

This scans your Rust code and generates:
- TypeScript interfaces for all structs
- Type-safe client functions
- Query/mutation names and input types

**Output:**
```
frontend/src/lib/forge/
├── client.ts      # FORGE client
├── types.ts       # Generated types
└── index.ts       # Re-exports
```

**When to run:**
- After adding/modifying Rust structs
- After adding/modifying functions
- Before starting frontend development

## forge migrate

Manage database migrations.

```bash
forge migrate [command]
```

**Subcommands:**

### `forge migrate up`

Apply pending migrations:

```bash
forge migrate up
```

### `forge migrate down`

Rollback the last migration:

```bash
forge migrate down
```

### `forge migrate status`

Show migration status:

```bash
forge migrate status
```

Output:
```
Migration Status:
  ✓ 0001_initial.sql (applied)
  ✓ 0002_add_users.sql (applied)
  ○ 0003_add_tasks.sql (pending)
```

### `forge migrate new`

Create a new migration:

```bash
forge migrate new <name>
```

Example:
```bash
forge migrate new add_comments
```

Creates:
```sql
-- migrations/0003_add_comments.sql

-- @up
-- Add your migration SQL here

-- @down
-- Add your rollback SQL here
```

## forge run

Start the FORGE server.

```bash
forge run [options]
```

**Options:**

| Option | Default | Description |
|--------|---------|-------------|
| `--port` | 8080 | HTTP port |
| `--workers` | CPU count | Number of workers |
| `--no-dashboard` | false | Disable dashboard |

**Examples:**

```bash
# Default (port 8080)
forge run

# Custom port
forge run --port 3000

# With specific workers
forge run --workers 4

# Without dashboard
forge run --no-dashboard
```

**Output:**
```
🔥 FORGE starting...
📦 Running migrations...
✅ Applied 0001_initial.sql
🚀 Gateway listening on http://localhost:8080
📊 Dashboard at http://localhost:8080/_dashboard
⚡ Worker 1 started
⚡ Worker 2 started
⏰ Scheduler started
```

## forge.toml Configuration

```toml
[project]
name = "my-app"
version = "0.1.0"

[gateway]
port = 8080
cors_origins = ["http://localhost:5173"]

[worker]
count = 4
capabilities = []

[database]
url = "${DATABASE_URL}"
max_connections = 10

[scheduler]
enabled = true

[dashboard]
enabled = true
auth = false  # Set true for production
```

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | Yes | PostgreSQL connection string |
| `FORGE_PORT` | No | Override gateway port |
| `FORGE_LOG` | No | Log level (debug, info, warn, error) |
| `FORGE_JWT_SECRET` | No | JWT signing secret |

**.env Example:**
```bash
DATABASE_URL=postgres://postgres:postgres@localhost:5432/myapp
FORGE_LOG=debug
FORGE_JWT_SECRET=your-secret-key-here
```

## Common Workflows

### Starting a New Project

```bash
# Create project with demo examples
forge new my-app --demo
cd my-app

# Start database
docker run -d --name forge-db -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=my_app \
  postgres:alpine

# Run migrations
forge migrate up

# Start server
cargo run
```

### Adding a New Feature

```bash
# Add query
forge add query get_user_profile

# Add mutation
forge add mutation update_user_profile

# Edit the generated files...

# Regenerate types
forge generate

# Test
cargo run
```

### Deploying

```bash
# Build release binary
cargo build --release

# Run migrations on production database
DATABASE_URL=$PROD_DB forge migrate up

# Start server
./target/release/my-app
```
