# CLI Reference

The `forge` CLI tool helps you create, develop, and manage FORGE projects.

## Installation

```bash
# Quick install (recommended)
curl -fsSL https://tryforge.dev/install.sh | sh

# Or build from source
git clone https://github.com/isala404/forge
cd forge
cargo install --path crates/forge

# For embedded PostgreSQL support (zero-dependency development)
cargo install --path crates/forge --features embedded-db
```

## Commands Overview

| Command | Description |
|---------|-------------|
| `forge new` | Create a new project |
| `forge dev` | Start development (postgres + backend + frontend) |
| `forge check` | Validate project configuration |
| `forge add` | Add a function |
| `forge generate` | Generate TypeScript types |
| `forge migrate` | Run database migrations |

## forge new

Create a new FORGE project. You must choose a template mode.

```bash
forge new <project-name> --demo|--minimal [options]
```

**Arguments:**
- `<project-name>` - Name of the project (also used as directory name)

**Template Modes (required - choose one):**

| Option | Description |
|--------|-------------|
| `--demo` | Full demo project with working examples (User CRUD, jobs, workflows, cron tasks, external API actions, complete frontend UI) |
| `--minimal` | Clean project with just the structure (empty directories with commented examples, starter frontend) |

**Additional Options:**

| Option | Description |
|--------|-------------|
| `-o, --output` | Output directory (defaults to project name) |

**Examples:**

```bash
# Create a full demo project - learn FORGE with working examples
forge new my-app --demo

# Create a clean project - start fresh with just the scaffolding
forge new my-app --minimal
```

:::tip Choosing a template
- Use `--demo` if you're learning FORGE or want working examples to build from
- Use `--minimal` if you're experienced and want a clean slate
:::

**Demo project structure** (`--demo`):
```
my-app/
├── Cargo.toml
├── forge.toml           # FORGE configuration
├── .env                 # Environment variables
├── src/
│   ├── main.rs          # Entry point with registered functions
│   ├── schema/
│   │   ├── mod.rs
│   │   └── user.rs      # User model example
│   └── functions/
│       ├── mod.rs
│       ├── users.rs     # CRUD queries/mutations
│       ├── export_users_job.rs
│       ├── heartbeat_stats_cron.rs
│       ├── account_verification_workflow.rs
│       └── get_bitcoin_price_action.rs
├── migrations/
│   └── 0001_initial.sql # User tables migration
└── frontend/
    ├── package.json
    ├── src/
    │   ├── routes/+page.svelte  # Full demo UI
    │   └── lib/forge/           # Generated types & API
    └── ...
```

**Minimal project structure** (`--minimal`):
```
my-app/
├── Cargo.toml
├── forge.toml
├── .env
├── src/
│   ├── main.rs          # Entry point with commented examples
│   ├── schema/
│   │   └── mod.rs       # Empty, with usage comments
│   └── functions/
│       └── mod.rs       # Empty, with usage comments
├── migrations/
│   └── 0001_initial.sql # Empty migration template
└── frontend/
    ├── package.json
    ├── src/
    │   ├── routes/+page.svelte  # Starter page
    │   └── lib/forge/           # Minimal types
    └── ...
```

## forge dev

Start the full development environment with embedded PostgreSQL, backend with hot reload, and frontend.

```bash
forge dev [options]
```

**Options:**

| Option | Default | Description |
|--------|---------|-------------|
| `-p, --port` | `8080` | Backend HTTP port |
| `--backend-only` | `false` | Only start backend (skip frontend) |
| `--no-open` | `false` | Don't open browser automatically |
| `--no-pg` | `false` | Skip embedded PostgreSQL (use external DATABASE_URL) |

**Examples:**

```bash
# Start everything (postgres + backend + frontend + open browser)
forge dev

# Use external database instead of embedded postgres
forge dev --no-pg

# Start only backend on port 3000
forge dev --backend-only --port 3000

# Start without opening browser
forge dev --no-open
```

**What happens:**

1. **Embedded PostgreSQL** starts (data stored in `./pg_data/`, gitignored)
2. **Backend compiles** with `cargo build`
3. **Backend starts** with `cargo watch` for hot reload (watches `src/`, `migrations/`, `Cargo.toml` only - ignores frontend changes)
4. **Frontend starts** with `bun run dev`
5. **Browser opens** automatically

**Output:**

```
🚀 Starting FORGE development environment...

  ✓ cargo found
  ✓ bun found
  ✓ Loaded .env

  ⋯ Starting embedded PostgreSQL...
  ✓ Embedded PostgreSQL running on port 5433
    → Data: ./pg_data/

  ⋯ Compiling backend...
  ✓ Backend compiled successfully

  → Backend: http://localhost:8080
  → Dashboard: http://localhost:8080/_dashboard
  → Frontend: http://localhost:5173

✅ Development server running. Press Ctrl+C to stop.
```

:::info Embedded PostgreSQL
When built with `--features embedded-db`, forge dev automatically starts an embedded PostgreSQL instance. Data persists in `./pg_data/` between sessions. Use `--no-pg` if you prefer an external database.
:::

## forge check

Validate your project configuration and dependencies. This command performs comprehensive checks to ensure everything is set up correctly.

```bash
forge check [options]
```

**Options:**

| Option | Default | Description |
|--------|---------|-------------|
| `-c, --config` | `forge.toml` | Path to configuration file |
| `--no-db` | `false` | Skip database connectivity check |

**What it checks:**

1. **forge.toml** - Valid TOML syntax, required sections ([project], [database], [gateway])
2. **Cargo.toml** - forge/forgex dependency exists
3. **Directory structure** - `src/`, `src/schema/`, `src/functions/`, `migrations/`
4. **Migration files** - Naming convention (NNNN_name.sql), `-- @up` marker
5. **Function files** - `#[forge::*]` macros present
6. **Schema files** - `#[forge::model]` macro present
7. **Code quality** - `cargo fmt --check`, `cargo clippy` with warnings as errors
8. **Environment** - `.env` file and `DATABASE_URL` variable
9. **Database** - PostgreSQL connection (optional, skip with `--no-db`)
10. **Frontend** - `package.json`, Svelte dependency, `.forge/svelte` runtime, `node_modules`
11. **Frontend linting** - ESLint (`bun run lint`), Prettier (`bun run format:check`)

**Example output:**

## forge add

Add a new function to your project.

```bash
forge add <type> <name>
```

**Arguments:**
- `<type>` - Function type: `query`, `mutation`, `action`, `job`, `cron`, `workflow`
- `<name>` - Function name (snake_case)

**Examples:**

```bash
# Add a query
forge add query list_users

# Add a mutation
forge add mutation create_user

# Add a job
forge add job send_email

# Add a cron
forge add cron daily_cleanup

# Add a workflow
forge add workflow process_order
```

**Generated Files:**

Query:
```rust
// src/functions/queries/list_users.rs
use forge::prelude::*;

#[forge::query]
pub async fn list_users(ctx: &QueryContext) -> Result<Vec<User>> {
    todo!("Implement list_users")
}
```

Job:
```rust
// src/functions/jobs/send_email.rs
use forge::prelude::*;

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SendEmailInput {
    // Add input fields
}

#[forge::job]
pub async fn send_email(ctx: &JobContext, input: SendEmailInput) -> Result<()> {
    todo!("Implement send_email")
}
```

## forge generate

Generate TypeScript types from your Rust code.

```bash
forge generate
```

This scans your Rust code and generates:
- TypeScript interfaces for all structs
- Type-safe client functions
- Query/mutation names and input types

**Output:**
```
frontend/src/lib/forge/
├── client.ts      # FORGE client
├── types.ts       # Generated types
└── index.ts       # Re-exports
```

**When to run:**
- After adding/modifying Rust structs
- After adding/modifying functions
- Before starting frontend development

## forge migrate

Manage database migrations.

```bash
forge migrate [command]
```

**Subcommands:**

### `forge migrate up`

Apply pending migrations:

```bash
forge migrate up
```

### `forge migrate down`

Rollback the last migration:

```bash
forge migrate down
```

### `forge migrate status`

Show migration status:

```bash
forge migrate status
```

Output:
```
Migration Status:
  ✓ 0001_initial.sql (applied)
  ✓ 0002_add_users.sql (applied)
  ○ 0003_add_tasks.sql (pending)
```

### `forge migrate new`

Create a new migration:

```bash
forge migrate new <name>
```

Example:
```bash
forge migrate new add_comments
```

Creates:
```sql
-- migrations/0003_add_comments.sql

-- @up
-- Add your migration SQL here

-- @down
-- Add your rollback SQL here
```

## forge.toml Configuration

```toml
[project]
name = "my-app"
version = "0.1.0"

[gateway]
port = 8080
cors_origins = ["http://localhost:5173"]

[worker]
count = 4
capabilities = []

[database]
url = "${DATABASE_URL}"
max_connections = 10

[scheduler]
enabled = true

[dashboard]
enabled = true
auth = false  # Set true for production
```

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | No* | PostgreSQL connection string (*not needed with embedded postgres) |
| `FORGE_PORT` | No | Override gateway port |
| `FORGE_LOG` | No | Log level (debug, info, warn, error) |
| `FORGE_JWT_SECRET` | No | JWT signing secret |

**.env Example:**
```bash
DATABASE_URL=postgres://postgres:postgres@localhost:5432/myapp
FORGE_LOG=debug
FORGE_JWT_SECRET=your-secret-key-here
```

## Common Workflows

### Starting a New Project

```bash
# Create project with demo examples
forge new my-app --demo
cd my-app

# Start development (embedded postgres + backend + frontend)
forge dev
```

That's it! No Docker, no external database setup needed.

### Using an External Database

```bash
# Create project
forge new my-app --demo
cd my-app

# Set up your database URL
echo "DATABASE_URL=postgres://user:pass@localhost:5432/myapp" >> .env

# Start with external database
forge dev --no-pg
```

### Adding a New Feature

```bash
# Add query
forge add query get_user_profile

# Add mutation
forge add mutation update_user_profile

# Edit the generated files...

# Regenerate types
forge generate

# Test
forge dev
```

### Using Docker Compose

For containerized development:

```bash
# Start all services
docker compose up --build

# Or run in background
docker compose up -d --build
```

### Deploying to Virtual Machine

```bash
# Build release binary
cargo build --release

# Copy to server
scp target/release/my-app user@server:/app/

# On server: run with systemd or supervisor
DATABASE_URL=postgres://user:pass@db/myapp /app/my-app
```

### Deploying with Docker

```bash
# Build production image
docker build -t my-app .

# Run with external PostgreSQL
docker run -d \
  -e DATABASE_URL=postgres://user:pass@host/db \
  -p 8080:8080 \
  my-app
```
